# Content Diary — Prototype Product Spec

## 1. 目的

漫画・アニメ・映画・小説などの「自分が触れたコンテンツ」を、一か所にまとめて記録する個人向けサービス。

中心に置くのは一般的な作品データベースではなく、次の個人的な記録です。

- 何を見た／読んだか
- どの程度好きだったか
- そのとき何を感じたか
- 自分の中でどの作品が上位か
- 次に何を見る／読むとよさそうか

個人利用だけでも十分な価値が成立することを第一条件とします。

## 2. 対象コンテンツ

初期カテゴリ:

- 漫画
- アニメ
- 映画
- 小説

将来はドラマ、ゲーム、ドキュメンタリー、Web作品などを追加可能な設計とします。

## 3. 情報モデル

作品ごとに以下を保存します。

- タイトル
- カテゴリ
- ステータス
  - 見た／読んだ
  - 進行中
  - 見たい／読みたい
  - 保留
- 個人評価: 1〜10
- お気に入り
- タグ
- 一言メモ／感想
- 登録日
- 更新日

今後の候補:

- 作者・監督・スタジオ
- 公開年
- 巻数／話数／シーズン
- 進捗
- 視聴・読了日
- 再視聴／再読回数
- 作品別の複数評価軸
- 印象に残った場面・引用ではない自分のメモ

## 4. UI方針

スマートフォンを最優先します。

### ホーム

- 検索
- 登録作品数などの簡易サマリー
- マイランキング
- 最近追加した作品
- 現在進行中の作品

### ライブラリ

- 全作品
- カテゴリ絞り込み
- ステータス絞り込み
- お気に入り絞り込み
- 評価順／更新順の並び替え

### 追加・編集

入力負荷を上げすぎず、最低限の操作で記録できるようにします。

### おすすめ

登録履歴から好みを読み取り、次に触れる作品候補を提示します。

初期の本実装では、LLMとWeb検索を組み合わせ、単に有名作品を出すのではなく、ユーザーの評価・タグ・カテゴリ傾向・過去の感想に基づいて理由付きで推薦する想定です。

将来的に利用者が増えた場合は、類似ユーザーの評価を利用する協調フィルタリングを組み合わせます。

## 5. ランキング

ランキングはサービス全体の人気順ではなく、まず「自分のランキング」を中心にします。

基本順位:

1. 個人評価
2. お気に入り
3. 更新日時

将来はカテゴリ別ランキング、年別ランキング、「世界観が好き」「感情を揺さぶられた」などのタグ別ランキングを追加可能にします。

## 6. プロトタイプの技術方針

初期版は依存関係を持たない静的Webアプリとします。

- HTML / CSS / JavaScript
- `localStorage` 保存
- ビルド不要
- GitHub Pagesでそのまま公開可能

目的はバックエンドを先に作ることではなく、実際にスマートフォンで触って「記録しやすいか」「一覧しやすいか」「ランキングが見やすいか」を検証することです。

## 7. プロトタイプで意図的に未実装

- ログイン
- クラウド同期
- 外部作品API
- 本物の生成AI API
- SNS機能
- コメント／フォロー

これらは基本体験の検証後に追加します。
